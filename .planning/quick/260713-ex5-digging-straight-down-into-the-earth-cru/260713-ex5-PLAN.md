<objective>
Fix the "digging straight down falls into open void forever" bug by giving every generated
world column a real, deterministic bottom: a LAVA band at the floor of the multipass
generator's column region, backstopped by an unconditional BEDROCK fill for anything that
ever streams below that region.

Purpose: Root-caused in `src/world/multipass_generator.gd` and the godot_voxel addon source
(`addons/godot_voxel/generators/multipass/voxel_generator_multipass_cb.cpp`). The generator
(`MineshaftGenerator extends VoxelGeneratorMultipassCB`) only ever fills terrain for Y inside
`[column_base_y_blocks*16, (column_base_y_blocks+column_height_blocks)*16)` -- with the addon's
UNCHANGED defaults (`column_base_y_blocks=-4`, `column_height_blocks=8`) that is world Y in
`[-64, 64)`. Anything outside that range is generated by the virtual method
`_generate_block_fallback(out_buffer, origin_in_voxels)`, which the class doc explicitly
recommends implementing as "air above, bedrock below" -- but `multipass_generator.gd` does
NOT implement it at all (confirmed: no `_generate_block_fallback` anywhere in the 739-line
file). godot_voxel's own C++ implementation (`voxel_generator_multipass_cb.cpp` lines
36-49, `generate_block_fallback_script` lines 58-78) calls this GDVIRTUAL unconditionally for
any block whose Y falls outside the column region; with no script override, the virtual call
silently no-ops and the block buffer stays at its zero-filled default (voxel id 0 = AIR_ID).
So a player who digs straight down past world Y=-64 (64 voxels -- an entirely reachable mining
depth, well past the existing `MINESHAFT_DEPTH_GATE=-8`) falls out of the generated column
into permanently-unimplemented fallback blocks: literal open void, forever. This is a design
gap, not a flaky edge case -- it reproduces on every column, every seed, at exactly Y=-64.

Output:
  1. `multipass_generator.gd` pass 0 (`_generate_base_terrain`) writes a `LAVA_BAND_THICKNESS`
     (4 voxels) thick LAVA_ID band at the very bottom of every column (`y < area_min.y +
     LAVA_BAND_THICKNESS`), anchored dynamically to `area_min.y` (which for pass 0, extent 0,
     is always exactly the column's floor -- so this stays correct even if
     `column_base_y_blocks` is ever retuned). No biome's surface ever comes remotely close to
     this depth (the lowest surface in the game is the OCEAN seabed at
     `sea_level - OCEAN_FLOOR_DEPTH - OCEAN_FLOOR_RELIEF` =~ Y=-1), so the band never
     collides with normal terrain.
  2. A new `_generate_block_fallback(out_buffer, origin_in_voxels)` override: BEDROCK_ID for
     every block below the column floor (unconditional, infinite downward -- this is the
     absolute backstop that guarantees no void regardless of how far a runaway fall or
     mineshaft-corridor carving reaches), AIR_ID for every block above the column ceiling
     (open sky), matching the class doc's own suggested pattern.
  3. Two new VoxelBlockyLibrary entries in `terrain.tscn` (index 13 = bedrock, index 14 =
     lava) so the new voxel ids actually render/collide.

Known, accepted interaction (not fixed here, out of scope for this bug): `_generate_mineshaft_
pass` (pass 1) always stamps its corridor template's local Y=0 at `area_min.y` -- i.e. mineshaft
pieces are always carved starting at the column floor, the same Y range as the new lava band.
On the ~35% of columns where a mineshaft spawns, its template overrides may locally replace
some lava-band cells with corridor air/walls. This does not reintroduce the void bug (the
BEDROCK fallback one block below is completely independent of pass 1 and always holds), it
only means a minority of columns show a mineshaft floor instead of a lava floor at the very
bottom. Flagged for a future phase if visual consistency there matters; not part of this fix.
</objective>

  ## VoxelGeneratorMultipassCB override: called for every block OUTSIDE the column region
  ## (Y < column_base_y_blocks*CHUNK_SIZE, or Y >= (column_base_y_blocks+column_height_blocks)
  ## *CHUNK_SIZE). Ex5 bugfix: this was NOT implemented before, so godot_voxel's default
  ## (zero-filled = AIR_ID) buffer was used -- a player digging straight down past the column
  ## floor (world Y=-64 with the addon's default column_base_y_blocks=-4) fell into permanent
  ## open void. Below the column: solid BEDROCK, unconditionally and infinitely -- the true
  ## backstop that guarantees no void regardless of what pass 1 (mineshaft carving) does inside
  ## the column itself. Above the column: AIR (open sky), matching the class doc's own example.
  func _generate_block_fallback(out_buffer: VoxelBuffer, origin_in_voxels: Vector3i) -> void:
      var column_floor_y: int = column_base_y_blocks * CHUNK_SIZE
      if origin_in_voxels.y < column_floor_y:
          out_buffer.fill(BEDROCK_ID)
      else:
          out_buffer.fill(AIR_ID)
