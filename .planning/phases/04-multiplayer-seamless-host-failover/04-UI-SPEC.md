# Phase 4 — UI Design Contract

> Covers every user-facing surface introduced in this phase (DOC-06).

**Source authority:** DOCS.md §6, 04-CONTEXT.md, existing Phase 1-3 codebase.
All upstream decisions are pre-populated. No design-system questions were re-asked.

## Spacing Scale

Pre-populated from Phase 1 UI-SPEC and confirmed in `inventory_slide_in.gd`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Heart gaps, icon-to-label separation in nameplates |
| sm | 8px | Cell gap in friend/session lists, button row separation |
| md | 16px | Panel content margin (all slide-in panels), form field vertical spacing |
| lg | 24px | Section separation inside panels |
| xl | 32px | Reserved — not used in Phase 4 surfaces |
| 2xl | 48px | Bottom-sheet peek height (inherited from inventory_slide_in.gd PEEK_HEIGHT) |
| 3xl | 64px | Mobile touch-button size (TouchScreenButton minimum — 64×64 px) |

Exceptions:
- **Mobile touch targets for Chat and Invite buttons:** 64×64 px (3xl), matches PaletteButton and InventoryButton in `mobile_overlay.tscn`.
- **Player nameplate label:** no explicit container; uses 4px vertical padding, no background.
- **Network HUD indicator:** 16×16 px dot + 8px gap to text — smaller than the xs token to keep the HUD visually quiet.
- **Online/offline status dot in friends list:** 10×10 px ColorRect — between xs and sm, acceptable exception for a status indicator.

## Typography

Inherited from `cubicraftia.tres`. Phase 4 uses all four existing rungs; no new sizes.

| Role | Size | Weight | Line Height | Usage in Phase 4 |
|------|------|--------|-------------|-----------------|
| Body | 16px | 400 (regular) | 1.5 | Chat message text, friend status lines, form field input |
| Label | 14px | 600 (semibold) | 1.3 | Section headings inside panels, button labels, invite token display, rate-limit toast |
| Heading | 20px | 600 (semibold) | 1.2 | Panel titles (Friends, Players, Handover overlay title) |
| Display | 28px | 600 (semibold) | 1.2 | Reserved — title screen only (Phase 6); not used in Phase 4 |

**Nameplate (Label3D in-world):** 14px equivalent at 1 m distance from camera (maps to Label3D `pixel_size` of 0.004). Weight semibold. No line wrap. Truncate at 16 characters with ellipsis.

**Chat message history:** Body 16px regular. Maximum 40 messages visible; older messages silently purged from the display list (performance cap per prompt). Each message line: `[HH:MM] <username>: message text`.

## Surfaces Specification

### Surface 1: Title / Sign-in Flow

**Scope for Phase 4:** Minimal usable sign-in surface only. Full FTUE (avatar creation, world-pick, tutorial) is Phase 6. Phase 4 ships exactly: Sign in form, Create account form, the session routing gate (signed-in → world; not signed-in → sign-in).

**Layout:** Full-screen `CanvasLayer` (layer 10) with `PanelContainer` centred (480px wide, auto-height on desktop; full-width on mobile with 16px horizontal margin). Panel background: dominant navy at 0.95 alpha, rounded 16px corners.

**Sign-in tab / Create account tab:** Two `Button` nodes styled as tabs using the existing `_apply_tab_style` pattern from `inventory_slide_in.gd`. Active tab: 2px accent-yellow bottom border. Inactive: brick white at 70% alpha.

**Form fields:** Godot `LineEdit` nodes. Normal border: 1px brick-white at 50%. Focused border: 2px accent-yellow (reuse `StyleBox_focus` from `cubicraftia.tres`). Password fields: `secret = true`. Vertical spacing between fields: 16px (md).

**Buttons:**
- Primary CTA: full-width Button using `StyleBox_button_normal`. Label: "Sign in" / "Create account".
- OAuth buttons (Sign in with Apple, Sign in with Google): same button style, 16px gap between them, icon (16×16 TextureRect) + label inline. Apple button: brick-white text on navy. Google button: same style (no special colour — project ethos avoids platform brand colours in UI chrome).

**Age checkbox (Create account only):** `CheckBox` node. Label: "I am 13 or older." Body 16px. No custom styling required beyond theme default.

**Email verification notice (Create account confirmation):** Label body 16px at 70% alpha brick-white. Copy: "A verification link has been sent. You can play now — some features unlock after verification."

**Error state:** Label below the submit button. 14px label weight. Color: `#D63828` destructive red. Icon: 16×16 TextureRect (`icon_error.png`). No modal.

### Surface 3: Sessions Browser

**Presentation:** Sessions browser is embedded within the Friends List panel — not a separate panel. When a friend has an open session, their row displays "Open · [world name]" in the status line and shows a "Join" button.

There is no standalone sessions browser screen. Friends-only social model means the only discovery surface is the friends list.

**Join flow on tap:** Tapping "Join" triggers:
1. Button enters loading state (spinner replaces label, button disabled). Spinner: 16×16 AnimatedSprite2D or a simple ProgressBar with `indeterminate` styling.
2. WebRTC handshake happens in background.
3. On success: panel closes, world loads, player appears next to host.
4. On failure: button re-enables, error label appears below: "Couldn't join — [reason]. Try again." (14px, destructive red).

**i18n keys (new):**
```
ui.session.open_status
ui.session.join_loading
ui.session.join_failed
```

### Surface 4: Invite Link Generation

**Entry point:** Pause menu (settings_menu.tscn extension) — new "Players" tab (see Surface 6). Inside Players tab, a full-width "Invite" button above the player list.

**On tap "Invite":**
1. Go service generates a 26-char base32 token. Discovery server returns the full link.
2. Modal dialog appears (PanelContainer, 400px wide, modal overlay behind it). Modal overlay: full-screen ColorRect, navy `#1B2C56` at 60% alpha.
3. Modal content:
   - Heading: "Invite a friend" (20px semibold)
   - The short link displayed in a `LineEdit` (read-only, `editable = false`) — 100% width, body 16px. Monospace-style: no actual font change needed; the token is alphanumeric.
   - TTL countdown label (14px, brick-white 70% alpha): "Expires in [HH:MM:SS]" — updated every second via a Timer.
   - Two buttons side-by-side (8px gap):
     - "Copy link" (primary style, 50% width): copies to `DisplayServer.clipboard_set()`.
     - "Share" (primary style, 50% width): triggers OS share sheet (`OS.shell_open("url")` on mobile, clipboard fallback on desktop).
   - After copy: "Copy link" button label changes to "Copied!" for 2 seconds then reverts. No toast.
   - "Close" button (full-width, secondary style — no fill, 1px brick-white border) at bottom.

**Secondary style button (new in Phase 4):** `StyleBoxFlat`, background transparent, border 1px brick-white at 80% alpha, rounded 8px. Text: brick white. Hover: border brightens to 100% alpha. This style is used only for non-destructive secondary actions (Close, Cancel) and must be added to `cubicraftia.tres` as `StyleBox_button_secondary`.

### Surface 5: Join-From-Invite Flow

**Link handling:** Universal Link / App Link opens the game. If not signed in: sign-in panel appears full-screen. After sign-in, the join flow resumes automatically.

**Join screen (while WebRTC handshake is in progress):** Full-screen `CanvasLayer` (layer 20 — above HUD), dark overlay (ColorRect, navy 80% alpha). Centred `VBoxContainer`:
- Heading: "Joining [host username]'s world…" (20px semibold, brick white)
- Spinner: AnimatedSprite2D or 32×32 rotating TextureRect — not a ProgressBar (indeterminate progress bars are banned on Tier-3 per performance note; use a simple 4-frame sprite instead)
- Status label (14px, brick-white 70% alpha): "Connecting…" → "Loading world…" → gone on success

**On join success — "New friends" toast:**
- Toast shown at top of screen for 4 seconds (matches existing Toasts pattern from `src/autoload/toasts.gd`)
- Copy: "You and [host username] are now friends."
- Toast border: 2px accent yellow (`#F5C30D`). Background: dominant navy. Icon: 16×16 friend icon (new: `icon_friends.png`).

**On join failure:**
- Join screen replaced by full-screen error state (same overlay).
- Heading: "Couldn't join" (20px semibold, destructive red `#D63828`)
- Body: reason (14px, brick-white): "The session is full." / "The invite has expired." / "Connection failed — check your internet."
- Single button: "Back" (secondary style, 200px centred).

### Surface 6: Pause Menu — Players Tab

**Extension of `settings_menu.tscn`:** A new "Players" tab is inserted as the first tab in the settings menu. The existing sections (Graphics, Brick Packs, About) move one tab to the right under a "Settings" tab.

**Tab row:** `HBoxContainer` at the top of the settings menu VBox. Two tabs: "Players" and "Settings". Styled using the existing `_apply_tab_style` pattern. 2px accent-yellow bottom border on active tab.

**Players tab content (host view):**

1. **Invite button** — full-width Button ("Invite a friend"), primary style. Opens Surface 4 modal on tap. Only visible when session has fewer than 4 players.

2. **Player list** — `VBoxContainer`. One row per connected player (including the host, who is listed first). Row height: 56px.

   Each row:
   - Builder colour swatch (24×24 ColorRect, builder's primary brick colour index from the 18-colour palette — looked up at runtime)
   - Username label (16px body)
   - "(Host)" label (14px, brick-white 60% alpha) — shown only next to the host's own name
   - Connection quality indicator (right-aligned): 3-bar signal-strength icon (TextureRect, 16×16). Bars filled proportional to peer RTT: <50ms = 3 bars, 50-150ms = 2 bars, >150ms = 1 bar. Uses cached textures, not per-frame text.
   - If frozen: accent-yellow ring (2px border on the row PanelContainer) + lock icon (16×16 `icon_freeze.png`)
   - Host-only admin buttons (shown only to the host, only on non-host player rows):
     - "Kick" (80px, destructive red style): requires confirmation inline (row expands to show "Kick [username]? They can rejoin via invite." + "Confirm kick" + "Cancel" buttons)
     - "Freeze / Unfreeze" (80px, accent-yellow border when frozen, normal when not): toggle, no confirmation required
     - "Roll back" button is NOT per-player — it is a separate full-width danger button below the player list (see below).

3. **Roll back section** (host only, below player list):
   - `HSeparator`
   - Warning label (14px, brick-white 60% alpha): "Restore the world to ~30 minutes ago. Affects everyone."
   - "Roll back world" button (full-width, destructive red style). On tap: confirmation modal (separate `PanelContainer` overlay) with heading "Roll back world?" (20px semibold), body "This restores everyone to the last automatic snapshot, about 30 minutes ago. All builds since then will be lost." (16px), and two buttons: "Roll back" (destructive red, 160px) + "Cancel" (secondary style, 160px), 8px gap.

**Players tab content (non-host view):**
- Player list only (no Kick/Freeze/Roll back controls visible).
- Connection quality indicators are shown.
- Read-only.

**"[Player] is laggy" soft warning:** Appears inline within the player's row — a small amber label "Laggy" (14px, relay amber `#E8890C`) shown when 3 consecutive keepalives are lost. Disappears automatically when connectivity recovers. Not a toast.

### Surface 7: Chat Overlay

**Desktop trigger:** `Enter` key opens chat (per DOCS §6.6 and §7.5 control lock). The chat input row slides up from the bottom of the HUD, above the hotbar.

**Mobile trigger:** New "Chat" TouchScreenButton (64×64 px) anchored bottom-left, above the VirtualJoystick (offset: 8px gap above joystick top edge). This is a new addition to `mobile_overlay.tscn`.

**Layout:** `CanvasLayer` (layer 5 — below pause menu, above world). Two sub-nodes:

1. **Chat history panel** — `PanelContainer` anchored to the left edge, bottom of screen, above hotbar. Width: 360px desktop / 100% viewport width on mobile. Max height: 240px (shows last ~8 messages; scrolls). Background: dominant navy at 0.80 alpha (slightly more transparent than slide-in panels to keep the world visible). Rounded top-right corner (16px); other corners flush with screen edge on desktop. On mobile: rounded top corners (16px), flush bottom.

   Message format per line: `[14px label, brick-white 50% alpha] HH:MM  [14px body, brick white] username: message text`
   
   Filtered messages: displayed as `username: [filtered]` in brick-white 40% alpha italic — sender sees their original text (client-side: the sender's own message is shown unfiltered locally; the filtered version is what peers receive and display).

   History panel is hidden when chat is closed. It auto-shows for 5 seconds when a new message arrives and the panel is closed, then auto-hides. No re-open animation for the auto-show; just fade in (0.1s).

2. **Chat input row** — `HBoxContainer` anchored to the bottom of the history panel (or bottom of HUD area if history panel is hidden). Width matches history panel. Height: 48px. Content: `LineEdit` (expand fill) + "Send" `Button` (80px wide).

   LineEdit: placeholder "Message…" (body 16px, brick-white 40% alpha). Max character length: 200. On `Enter` or "Send" button: message dispatched, field cleared, input row closes.

   Rate limit feedback: if the rate limit is hit (5 per 10s), the LineEdit becomes disabled for the remainder of the window, and a label appears above it: "Slow down — you can send another message in [Ns]." (14px, relay amber). The label disappears when the window resets.

**Mute per player:** Long-press on a message in the history panel reveals a context menu (small `PanelContainer`, 160px wide, navy background) with "Mute [username]" and "Report message". Mute is a local-only display filter — muted messages still arrive on the client but are not rendered. A mute indicator (speaker-crossed icon, 16×16 `icon_mute.png`) appears next to the muted player's username in the Players tab.

**Performance:** History capped at 40 messages in memory. No per-frame text shaping. The history `RichTextLabel` (or `VBoxContainer` of `Label` nodes) is updated only on new-message signal, not in `_process`.

### Surface 8: Player Nameplates (In-World)

**Implementation:** `Label3D` node parented to each remote builder's head bone (or a fixed offset above the builder's root node: +2.2 m Y).

**Visual spec:**
- Text: builder username (truncate at 16 chars with "…")
- Font size: 14px equivalent (`pixel_size = 0.004`, `font_size = 14`)
- Font weight: semibold 600
- Color: builder's primary brick colour from the 18-colour palette (set at runtime via `Label3D.modulate`)
- Outline: 1px black (`#000000`) outline via `Label3D.outline_size = 1` to ensure legibility on any background
- Billboard mode: `Label3D.billboard = BaseMaterial3D.BILLBOARD_ENABLED` — always faces camera
- Distance fade: `Label3D.visibility_range_end = 20.0` (metres), `visibility_range_end_margin = 4.0` — fades from full opacity at 16m to invisible at 20m
- No background; no panel behind the text

**Toggleable in settings:**
- Settings menu "Settings" tab → new `CheckBox` "Show player names". Default: on. Persisted to `user://settings.cfg` [multiplayer] section: `show_nameplates=true`.
- When toggled off: all nameplate `Label3D` nodes are hidden via `visible = false`.

**Performance:** No per-frame text update. Username is set once on remote builder spawn and is not re-shaped each frame. The `Label3D` update is O(1) per builder join/leave event.

**i18n keys (new):**
```
ui.settings.show_nameplates
```

### Surface 9: Handover Screen

**Trigger:** Emitted by `NetworkManager` autoload when host failover begins.

**Layout:** Full-screen `CanvasLayer` (layer 100 — topmost, above all HUD and menus). Single `VBoxContainer` centred in the viewport.

**Background:** Full-screen `ColorRect`, dominant navy `#1B2C56` at 0.88 alpha. Blocks interaction with the game world but does not block the game loop.

**Content (centred, 400px max-width container):**
- Icon: brick icon or Cubicraftia logo (TextureRect, 48×48 px, brick-white tinted)
- Heading: "Switching host — keeping the world…" (20px semibold, brick white)
- Subtitle: "Hold on a moment." (16px regular, brick-white 70% alpha)
- Spinner: 32×32 rotating TextureRect (`icon_spinner.png`, 4-frame, rotates at 2 Hz — 1 frame per 0.5s). Not an indeterminate ProgressBar (Tier-3 performance constraint).

**Auto-dismiss:** `NetworkManager` emits a `host_failover_complete` signal when WebRTC reconnect to the new host succeeds. The handover screen listens for this signal and removes itself (not hides — `queue_free()`) after a 0.22s fade-out tween (matching panel animation duration).

**If failover takes >8 seconds:** The subtitle updates to "This is taking longer than expected…" (16px, relay amber `#E8890C`). No timeout/give-up logic in the UI; that is `NetworkManager`'s responsibility.

**Not dismissible by player:** No close button. No Escape key handler.

**i18n keys (new):**
```
ui.handover.heading
ui.handover.subtitle
ui.handover.subtitle_slow
```

### Surface 10: Network Status HUD

**Position:** Top-right corner of the main HUD `CanvasLayer`, 16px from the right edge and 16px from the top (or below the safe-area inset on mobile). Anchored `ANCHOR_TOP_RIGHT`.

**Visible only in multiplayer sessions** (hidden in solo sessions where the session peer count is 1). Gated by `Features.is_multiplayer_enabled()` or peer count > 1.

**Content:**
- One row per remote peer (up to 3 peers). Each row (24px tall, 8px vertical gap):
  - 3-bar signal-strength icon (TextureRect, 16×16 px, `icon_signal_N.png` where N = 1/2/3 bars, cached not dynamic)
  - Peer username label (14px semibold, brick white, max 10 chars truncated)
  - "Relay" badge: `Label` with `StyleBoxFlat` background (relay amber `#E8890C`, rounded 4px, 4px horizontal padding, 2px vertical padding), text "Relay" (12px — only place in the UI where a 12px label is used, acceptable exception for a badge), brick white. Badge shown only when this peer's connection is via TURN relay. Badge is 8px to the right of the username.

**Laggy indicator:** When the soft-warning threshold is crossed (3 lost keepalives per CONTEXT Area 4), the signal icon for that peer switches to the 1-bar variant and gains `modulate = Color(#E8890C)` (relay amber tint) to draw attention. Recovers automatically.

**No per-frame label shaping:** `username` is set once per peer-connect event. RTT bucket (1/2/3 bars) updates at most once per second via a 1-second timer, not in `_process`.

**Performance:** All nodes are `Label` and `TextureRect` — no `RichTextLabel`, no GPU particles, no shaders.

**i18n keys (new):**
```
ui.netstatus.relay_badge
```

## Performance Constraints

| Surface | Constraint | Enforcement |
|---------|------------|-------------|
| Nameplates | No per-frame text shaping; set username once on spawn | Label3D property set in `_ready` of remote builder script |
| Chat history | Max 40 messages in DOM; older entries `queue_free()` silently | Enforced in chat autoload or chat panel controller |
| Network HUD | RTT bucket updates ≤1 Hz via Timer; username set once | Timer node, not `_process` |
