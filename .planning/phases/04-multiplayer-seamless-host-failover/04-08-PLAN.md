ProfanityFilter structure (PATTERNS.md lines 704-718):
```gdscript
class_name ProfanityFilter
extends RefCounted

const _WORD_LIST: Array[String] = ["badword1", "badword2"]  # ~20 stub words

static func filter(text: String) -> String:
    var result := text
    for word: String in _WORD_LIST:
        var regex := RegEx.new()
        regex.compile("(?i)\\b" + word + "\\b")
        result = regex.sub(result, "[filtered]", true)
    return result
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Chat message text | User-supplied; filtered by host before broadcast; all text paths run through ProfanityFilter |
| Per-player mute | Local-only; muted messages still arrive in memory but are not rendered |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-08-T | Tampering | Chat message injection bypassing profanity filter | mitigate | Host applies ProfanityFilter.filter() before relaying; host cannot be bypassed because all chat routes through host for delivery |
| T-04-08-D | Denial of Service | Chat flood (>5/10s) | mitigate | Rate limit enforced client-side before send; host-side: if a peer somehow bypasses client limit, host drops messages from peers beyond 5/10s (add host-side rate tracking in _receive_chat_from_peer) |
| T-04-08-I | Information Disclosure | Username truncation exposes partial names | accept | Max 10 chars in HUD display is a display choice; full username available in Players tab |
</threat_model>
