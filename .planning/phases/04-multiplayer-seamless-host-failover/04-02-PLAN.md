```sql
CREATE TABLE public.friendships (
  user_a     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  user_b     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  status     TEXT NOT NULL DEFAULT 'active',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (user_a, user_b),
  CONSTRAINT canonical_order CHECK (user_a < user_b)
);
CREATE INDEX friendships_user_a_idx ON public.friendships (user_a);
CREATE INDEX friendships_user_b_idx ON public.friendships (user_b);
ALTER TABLE public.friendships ENABLE ROW LEVEL SECURITY;
-- SELECT policy: user can see their own friendships
-- INSERT policy: user is one of the members + user_a < user_b
-- DELETE policy: user is one of the members
```

Invites table (04-RESEARCH.md lines 495-529):
```sql
CREATE TABLE public.invites (
  token        TEXT PRIMARY KEY,
  host_uid     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  session_id   TEXT NOT NULL,
  expires_at   TIMESTAMPTZ NOT NULL,
  redeemed_by  UUID REFERENCES auth.users(id) ON DELETE SET NULL,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
-- RLS: host views own, host creates, anyone redeems valid+unexpired+unredeemed via UPDATE
```

    signaling-server/internal/hub/relay.go:
    Relay message types: offer, answer, ice. Each relay message has a `to_uid` field. `Hub.relay(fromUID, toUID string, msg []byte)` finds the target connection and writes the raw message to it. If target not found, send back `{"v":1,"type":"error","payload":{"code":"peer_not_found","message":"Target peer is not connected"}}`.

    signaling-server/internal/hub/hub.go:
    The WebSocket hub. Struct `Hub` with `clients map[string]*Client` (keyed by uid), `sessions *SessionRegistry`, `mu sync.RWMutex`, `cfg *config.Config`. `Client` struct: `uid string`, `conn *websocket.Conn`, `send chan []byte`. `Hub.Run()` method manages a ticker for idle session pruning (every 60 s). `Hub.HandleConn(w http.ResponseWriter, r *http.Request)` upgrades WebSocket, verifies JWT from `Authorization: Bearer <token>` header (or `token` query param), registers client, reads messages in a loop. Message dispatch via `handleMessage(client *Client, raw []byte)`:
    - `register`: store uid → session_id mapping, notify friends who are online (send session_list if friends are online — in v1, send an empty session_list; friend lookup is done by the client via Supabase)
    - `publish_session`: call sessions.Register; broadcast `session_list` to connected friends (v1: skip broadcast, client polls via FriendsClient)
    - `unpublish_session`: sessions.Unregister
    - `offer`, `answer`, `ice`: relay to target uid
    - `update_host`: sessions.UpdateHost + relay notification to all peers of that session
    - Unknown type: send `{"v":1,"type":"error","payload":{"code":"unknown_type","message":"..."}}`

    Enforce 15-minute idle session timeout in `PruneIdle`. Enforce 4-peer max on `publish_session` (reject with error if max_peers > 4).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase JWT on WebSocket upgrade | Client must present valid Supabase JWT; unauthenticated connections rejected |
| RLS policies | Per-row authorization enforced by Postgres; Go server is not the authority for friendship visibility |
| coturn relay | Must be restricted mode (lt-cred-mech), never open relay |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-S | Spoofing | Go signaling server WebSocket auth | mitigate | VerifyJWT() called on every WebSocket upgrade; reject if token invalid/expired; uid extracted from verified `sub` claim |
| T-04-02-T | Tampering | Invite token single-use enforcement | mitigate | RLS UPDATE policy USING (redeemed_by IS NULL) makes the DB the authority; Go server and client cannot bypass this |
| T-04-02-D | Denial of Service | signaling server session cap | mitigate | 200-session soft cap logged as operator alert; 4-peer max enforced on publish_session |
| T-04-02-D2 | Denial of Service | coturn open relay abuse | mitigate | coturn deployed with lt-cred-mech + total-quota + no-loopback-peers per CONTEXT Area 2 specifics |
| T-04-02-SC | Tampering | Go dependency (nhooyr.io/websocket) | mitigate | Verify the module hash in go.sum is consistent; `go mod verify` must pass |
</threat_model>
