HTTP request pattern from 04-RESEARCH.md lines 583-605:
```gdscript
func _sign_in(email: String, password: String) -> void:
    var body := JSON.stringify({"email": email, "password": password})
    var headers := ["Content-Type: application/json", "apikey: " + _anon_key]
    $HTTPRequest.request(
        _supabase_url + "/auth/v1/token?grant_type=password",
        headers,
        HTTPClient.METHOD_POST,
        body
    )

func _on_request_completed(result, code, _headers, body):
    if result != HTTPRequest.RESULT_SUCCESS or code != 200:
        sign_in_failed.emit(tr("ui.signin.error_network"))
        return
    var json: Variant = JSON.parse_string(body.get_string_from_utf8())
    if json == null:
        sign_in_failed.emit(tr("ui.signin.error_network"))
        return
    _access_token = json.get("access_token", "")
    _refresh_token = json.get("refresh_token", "")
    _user_id = json.get("user", {}).get("id", "")
    _save_tokens()
    signed_in.emit(_user_id)
```

Token persistence (ConfigFile pattern from PATTERNS.md lines 230-236):
```gdscript
const AUTH_PATH := "user://auth.cfg"
const SECTION := "auth"

func _save_tokens() -> void:
    var cfg := ConfigFile.new()
    cfg.set_value(SECTION, "access_token", _access_token)
    cfg.set_value(SECTION, "refresh_token", _refresh_token)
    cfg.set_value(SECTION, "expires_at", _expires_at)
    cfg.save(AUTH_PATH)

func _load_tokens() -> void:
    var cfg := ConfigFile.new()
    if cfg.load(AUTH_PATH) == OK:
        _access_token = cfg.get_value(SECTION, "access_token", "")
        _refresh_token = cfg.get_value(SECTION, "refresh_token", "")
        _expires_at = cfg.get_value(SECTION, "expires_at", 0.0)
```

GoTrue endpoints (04-RESEARCH.md lines 558-569):
```
POST /auth/v1/signup               — email+password registration

```

Supabase REST (PostgREST) API for friends/invites:
```
GET    /rest/v1/friendships?select=*&or=(user_a.eq.<uid>,user_b.eq.<uid>)
POST   /rest/v1/friendships         — create friendship
DELETE /rest/v1/friendships?user_a=eq.<uid>&user_b=eq.<uid>
POST   /rest/v1/invites             — create invite record
PATCH  /rest/v1/invites?token=eq.<token>  — redeem invite (set redeemed_by)
GET    /rest/v1/profiles?id=eq.<uid>&select=username
GET    /rest/v1/profiles?username=ilike.<query>&select=id,username  — friend search
```
Headers for authenticated calls: `["Content-Type: application/json", "apikey: " + _anon_key, "Authorization: Bearer " + _access_token]`

Invite token generation (04-CONTEXT.md Area 3): 128-bit random, base32-encoded (26 chars). In GDScript: generate via `randi_range` calls to produce a random alphanumeric string, then POST to Go signaling server's `/invite` endpoint which returns the full link, OR generate the token locally and POST the record directly to Supabase. Use Supabase directly (no signaling server round-trip needed for token creation).

Base32 alphabet: "ABCDEFGHIJKLMNOPQRSTUVWXYZ234567" — but for URL-friendliness, use lowercase + digits: generate 26 random alphanumeric chars (a-z, 2-7). Implementation: `var chars := "abcdefghijklmnopqrstuvwxyz234567"; var token := ""; for i in 26: token += chars[randi() % chars.length()]`.

Email verification gate (04-CONTEXT.md Area 3):
- Unverified (email_confirmed_at is null): can play but cannot send invites or join sessions > 24h old
- After 7 days: block invite-send + block old sessions (client enforces; read _is_email_verified from user object)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GoTrue JWT token | Stored in user://auth.cfg; refresh before expiry; never logged or emitted in signals |
| Supabase anon key | Public key (safe to ship in client); access control enforced by RLS, not the anon key |
| Invite token | 26-char base32, 128-bit entropy, single-use enforced by DB RLS UPDATE policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-S | Spoofing | FriendsClient sign-in with stolen token | mitigate | Tokens stored in app sandbox (user://); platform sandboxing prevents other apps from reading; refresh tokens rotated on use |
| T-04-04-T | Tampering | Canonical UUID ordering for friendship insert | mitigate | UUID string comparison in GDScript enforces user_a < user_b before POST; DB CHECK constraint is the final authority |
| T-04-04-D | Denial of Service | Invite token enumeration | mitigate | 26-char base32 = 128-bit entropy; brute-force infeasible; tokens expire in 24h |
| T-04-04-I | Information Disclosure | access_token in logs | mitigate | Never push_warning or push_error the token value; log only first 8 chars for debug |
| T-04-04-E | Elevation of Privilege | Unverified account sends invites | mitigate | is_invite_send_allowed() gates invite creation on is_email_verified(); UI disables the button; server RLS is the hard gate |
</threat_model>
