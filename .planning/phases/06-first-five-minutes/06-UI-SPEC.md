## Spacing Scale

Inherited verbatim from Phase 5 UI-SPEC. No new tokens required.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, preset tile inner padding |
| sm | 8px | Button row gap, avatar part row separation, world card internal spacing |
| md | 16px | Panel content margin, form field vertical spacing, modal content padding |
| lg | 24px | Section separation inside avatar creator, title button stack gap |
| xl | 32px | Title screen vertical centering margin |
| 2xl | 48px | Bottom-sheet peek height (inherited) |
| 3xl | 64px | Mobile touch targets for overlay buttons (inherited) |

**Exceptions for Phase 6:**

- **Title screen button stack:** 16px (md) vertical gap between the four buttons in the VBoxContainer. The "Continue as [username]" accent button has an additional 8px (sm) bottom separator below it before the "Sign in" button.
- **Avatar preset grid:** 8px (sm) gap between preset tiles in the 4×2 GridContainer. Each preset tile: 72×72 px (larger than the sm/md grid — call this `avatar_preset_tile`, not an 8pt multiple; this is the single justified exception for visual thumb size).
- **Avatar part row option buttons (skin/shape/expression/accessories):** 48px minimum row height for touch target compliance (per DOCS §7.6). Option items within a row: 8px (sm) gap.
- **World card minimum height:** 96px. Internal padding: 12px top/bottom, 16px left/right. The 12px top/bottom padding is an exception (not a standard token) justified by the thumbnail aspect ratio constraint (256×144px).
- **FTUE narration label bottom-third strip:** 16px content margin left/right, 12px top/bottom. Full readable width: viewport width minus 32px horizontal.
- **Deep-link inline sign-in prompt:** compact form — 16px (md) content margin, 12px vertical field gap. Acceptable because this surface is intentionally reduced-chrome.

## Typography

Inherited from `cubicraftia.tres`. Phase 6 introduces one new size at the title (the Display rung was reserved for this in Phase 4 and Phase 5). One justified exception beyond the four-rung ladder is documented below.

| Role | Size | Weight | Line Height | Usage in Phase 6 |
|------|------|--------|-------------|-----------------|
| Body | 16px | 400 (regular) | 1.5 | Avatar creator body text, world card world name, new world modal form fields, FTUE narration lines, deep-link prompt body, invite-joiner toast text |
| Label | 14px | 600 (semibold) | 1.3 | Avatar section labels ("Head", "Body", "Legs", "Hand"), preset preset labels, world card date + mode badge text, world card context menu items, "Continue as [username]" subtitle line |
| Heading | 20px | 600 (semibold) | 1.2 | Avatar creator panel title, world select panel title ("Your Worlds"), new world modal title, deep-link prompt heading, FTUE step progress label "Step N/4" |
| Display | 28px | 600 (semibold) | 1.2 | Used in Phase 6 for the first time: world select screen primary heading "Your Worlds" on desktop only (not the title wordmark — see exception below) |

**Exception — Title Logo (TitleLogo rung):**
The Cubicraftia wordmark on the title screen is rendered at **96px semibold** (weight 600, line height 1.0). This is the fifth and final size rung, introduced once, restricted to exactly one element: the `Label` node `_logo_label` inside `title_scene.tscn`. This rung must NOT be reused for any other element in any phase. If the artist delivers an SVG/PNG wordmark asset (`assets/textures/ui/title_logo.png`), the Label is replaced by a `TextureRect` and this rung becomes moot. Until the asset ships, 96px semibold is the typographic stand-in.

**FTUE narration lines:** Body 16px regular at 1.5 line height, brick white. Maximum 2 lines of visible text before the label scrolls (auto-wrap enabled, max 80% of viewport width). The completion notification "That's it. The world is yours." uses Heading 20px semibold to give it perceptual weight above the step narrations.

**World card world name:** Body 16px semibold (uses the Body rung size with a semibold weight override — this is acceptable within the two-weight system because it reuses an existing weight and an existing size, not a new combination).

**Relay badge (inherited from Phase 4):** 12px label — the single existing exception for a compact badge; Phase 6 does not introduce a new 12px use.

**Accent (`#F5C30D`) is reserved for (Phase 6 additions to the Phase 5 list):**

2. Selected hotbar slot ring (inherited)
3. Active Auto graphics chip (inherited)

9. **Selected avatar part option ring** — 2px accent-yellow border around the currently selected option swatch (skin colour, head shape, expression, body colour, etc.).
10. **Selected avatar preset tile border** — 2px accent-yellow border on the active preset tile in the 4×2 grid.

These two badges reuse existing semantic colors in a new combination. They do not introduce new color values.

## Surfaces Specification

### NEW Surface 1: Title Screen (`title_scene.tscn`)

**Layout:** Full-screen `CanvasLayer` (layer 0). Background: `TextureRect` (expand mode: IgnoreSize, stretch_mode: Scale) using `assets/textures/title/title_bg.png`. ShaderMaterial on the TextureRect with a `uv_pan_speed: float = 0.002` uniform, panning the UV on the U axis at 0.002 units/second in `_process`. No separate 3D scene.

**Content column:** `VBoxContainer`, centred horizontally, anchored vertically at 20% from top (not dead centre — leaves room for the legal footer). Maximum width: 480px on desktop, full-width minus 32px on mobile.

**Logo block (top of column):**
- Logo: `Label` node `_logo_label`, text "Cubicraftia", 96px semibold (TitleLogo rung), brick white. When `assets/textures/ui/title_logo.png` exists: replace with `TextureRect`, 320×80px, `expand_mode = FIT_WIDTH_PROPORTIONAL`.
- Tagline: `Label` below the logo, text from `tr("ui.title.tagline")` — "Build. Survive. Play together." — Body 16px regular, brick-white 70% alpha.
- 24px (lg) gap below the tagline before the button stack.

**Intro animation:** On `_ready()`, logo and tagline start at `modulate.a = 0.0`. A single `Tween` runs: `tween_property(logo, "modulate:a", 1.0, 2.0)` with `set_trans(Tween.TRANS_SINE).set_ease(Tween.EASE_IN_OUT)`. The same tween also fades in the button stack after a 0.5s delay (`tween_interval(0.5)` chained before the button fade). Total visible latency: ~2.5s from `_ready` to full opacity.

**Button stack (VBoxContainer, 16px gap):**

1. **"Continue as [username]"** — shown only when `FriendsClient.is_signed_in()` is true at `_ready()`. `Button`, full-width, `StyleBox_button_continue` (accent yellow `#F5C30D` fill, navy text, rounded 8px — see new StyleBox below). Label: `tr("ui.title.continue_as").format({"username": FriendsClient.get_username()})`. On press: skip sign-in, avatar check → world_select_screen. 8px separator below this button before the standard buttons.
2. **"Sign in"** — `Button`, full-width, `StyleBox_button_normal`. Label: `tr("ui.title.sign_in")`. On press: open `sign_in_panel.tscn` (CanvasLayer layer 10), pre-select sign-in tab.
3. **"Create account"** — `Button`, full-width, `StyleBox_button_normal`. Label: `tr("ui.title.create_account")`. On press: open `sign_in_panel.tscn`, pre-select create-account tab.
4. **"Continue offline"** — `Button`, full-width, `StyleBox_button_secondary`. Label: `tr("ui.title.continue_offline")`. On press: skip sign-in, use default builder mesh, go to world_select_screen in offline mode (Friends button hidden).
5. **"Settings"** — `Button`, full-width, `StyleBox_button_secondary`. Label: `tr("ui.title.settings")`. On press: open `settings_menu.tscn` (same instantiate pattern as `main_scene._open_settings()`).

**Legal footer:** `HBoxContainer` anchored to the bottom-left of the CanvasLayer, 16px left margin, 16px bottom margin (safe-area-aware on mobile). Two `Button` nodes styled as link labels (no background, no border, `flat = true`): "Terms of Use" (`tr("ui.legal.terms_link")`) and "Privacy Policy" (`tr("ui.legal.privacy_link")`). Label 14px, brick-white 60% alpha. On hover: 100% alpha. On press: open `legal_viewer.tscn` (Phase 5 scene).

**Version string:** `Label` anchored bottom-right, 16px margin. Text: `"v" + ProjectSettings.get_setting("application/config/version")`. Label 14px, brick-white 40% alpha.

**Sign-in flow continuation:** `title_scene.gd` connects to `sign_in_panel.sign_in_complete` and `sign_in_panel.play_offline_requested` in `_ready()`. On `sign_in_complete`: check `FileAccess.file_exists("user://avatar.cfg")` — if missing, show avatar creator (CanvasLayer layer 10); if present, show world_select_screen. On `play_offline_requested`: show world_select_screen in offline mode. Also connects to `sign_in_panel.under_13_signup_required` to instantiate and show `parental_gate_panel.tscn`.

**Deep-link intercept:** `_ready()` connects to `DeepLinkHandler.invite_token_received`. On receipt: call `_handle_invite_deep_link(token)` — skips all title UI (title column `visible = false`), initiates inline sign-in if needed (Surface 6 below).

**Music:** `AudioStreamPlayer` node with no stream loaded in the scene. Will auto-play when `assets/audio/music/title_theme.ogg` is dropped in. Volume: -6 dB. `autoplay = true`. `stream_paused = true` if no stream (no crash). Fades out on scene transition via `Tween` (-6 dB → -80 dB over 0.5s).

### NEW Surface 2: Avatar / Builder Creator (`avatar_creator.tscn`)

**Layout:** Full-screen `CanvasLayer` (layer 10). Single `PanelContainer` centred, 560px wide on desktop, full-width minus 32px on mobile. Background: dominant navy at 0.95 alpha, rounded 16px corners. Maximum height: 90% of viewport height; vertical scroll if content overflows.

**Panel structure (HBoxContainer inside the PanelContainer, 16px content margin):**

Left column (2/3 width, desktop only — on mobile the layout is a single VBoxContainer):
- Section heading: `tr("ui.avatar.title")` — "Choose your builder" — Heading 20px semibold, brick white.
- Parts customiser `VBoxContainer` with 16px (lg) section gaps. Each section is an `HBoxContainer` (section label left, options right).

Right column (1/3 width, desktop only):
- `SubViewportContainer` — 256×256px, `stretch = true`. Shows the rotating builder preview (SubViewport renders `builder.tscn` mesh with `Builder.apply_avatar_config(cfg)` applied). Camera orbits at 0.4 rad/s. `update_mode = SubViewport.UPDATE_WHEN_VISIBLE`.
- On mobile: SubViewportContainer is placed at the top of the single-column layout, 128×128px.

**Part sections (in order):**

1. **Skin** — Label: `tr("ui.avatar.section_skin")` "Skin". 5 swatches (`ColorRect` nodes, 32×32px, 8px gap, circular via shader or using `draw_arc`). Colours: `#FDDCB5` (light), `#D4956A` (tan), `#A0614A` (medium), `#6B3A2A` (dark), `#3B1F16` (deep). Selected swatch: 2px accent-yellow ring. Minimum touch target: swatch occupies a 44×44px `Button` container.

2. **Head** — Label: `tr("ui.avatar.section_head")`. Two rows:
   - Shape row: 3 `Button` tiles (72×48px each, 8px gap). Shapes: square, round, tall. Each tile shows the head silhouette as a white icon on navy. Selected: 2px accent-yellow border.
   - Expression row: 5 `Button` tiles (48×48px, 8px gap). Expressions: neutral, happy, cool, surprised, sleepy. Icon-style face preview. Selected: 2px accent-yellow border.

3. **Body** — Label: `tr("ui.avatar.section_body")`. Two rows:
   - Torso colour: 10 colour swatches (same 32×32 swatch style as skin, 8px gap) using a subset of the 18-colour palette (the 10 most expressive colours: red, orange, yellow, lime, green, teal, blue, purple, pink, white).
   - Accessory: 3 `Button` tiles (64×48px, 8px gap). Options: "None" (blank icon), "Backpack" (icon), "Cape" (icon). Labels: 14px semibold below each icon. Selected: 2px accent-yellow border.

4. **Legs** — Label: `tr("ui.avatar.section_legs")`. Two rows:
   - Leg colour: same 10-swatch row as body colour.
   - Shoes: 3 `Button` tiles (64×48px, 8px gap). Options: "None", "Boots", "Sneakers". Same pattern as accessories.

5. **Hand** — Label: `tr("ui.avatar.section_hand")`. One row: 5 `Button` tiles (56×56px, 8px gap). Options: "None" (fist icon), "Pickaxe", "Lantern", "Flower", "Blank" (open hand). Selected: 2px accent-yellow border.

**Preset grid (above the part sections, below the title):**
- Label: `tr("ui.avatar.presets_label")` "Quick start" — Label 14px semibold, brick-white 70% alpha.
- `GridContainer`, 4 columns, 8px gap. 8 tiles, each 72×72px. Each tile: `Button` with a small builder silhouette icon (`assets/textures/ui/avatar_presets/preset_N.png`, 64×64px). On press: all 5 parts updated instantly. Active preset (if current config matches a preset): 2px accent-yellow border.
- "Randomise" `Button` (small, `StyleBox_button_secondary`, 120px wide) anchored bottom-right of the preset grid. Label: `tr("ui.avatar.randomise")` "Randomise". On press: random valid combination applied. The icon `icon_dice.png` (16×16, new asset) precedes the label text.

**Footer button row (HBoxContainer, 8px gap, bottom of panel):**
- "Done" `Button` — primary style, expand fill. Label: `tr("ui.avatar.done")` "Done". On press: write `user://avatar.cfg`, call `FriendsClient.save_avatar(cfg)` fire-and-forget, emit `avatar_complete`. Enabled at all times (default config is always valid).
- "Back" `Button` — secondary style, 120px. Label: `tr("ui.avatar.back")` "Back". On press: emit `avatar_cancelled`. title_scene returns to the appropriate prior state.

**Behaviour notes:**
- Every part change immediately calls `Builder.apply_avatar_config(cfg)` on the SubViewport builder instance.
- `user://avatar.cfg` is written on every preset tap (fire-and-forget) so progress is not lost if the player force-quits.
- The "Done" button does NOT require all parts to be explicitly selected — the default config (first skin, square head, neutral expression, first body colour, no accessory, first leg colour, no shoes, no hand item) is a valid avatar.

### NEW Surface 4: New World Modal

**Trigger:** "New world" button on Surface 3. Shown as an overlay `PanelContainer` (400px wide, auto-height, centred) over the world select screen. Modal overlay behind it: full-screen `ColorRect`, dominant navy `#1B2C56` at 60% alpha, `mouse_filter = MOUSE_FILTER_STOP`.

   - `LineEdit`, full-width, 40px height. Placeholder: `tr("ui.new_world.name_placeholder")` "My world". Default value: `tr("ui.new_world.name_placeholder")`. `keyboard_type = LineEdit.KEYBOARD_TYPE_DEFAULT`.

4. **Mode toggle:**

### NEW Surface 5: FTUE Overlay (`ftue_overlay.tscn`)

**Layout:** `CanvasLayer`, layer 20 (above all game UI at layer 10, below handover_screen at layer 100, below context menus at layer 25). The overlay is non-modal — the player can freely move, open inventory, mine, and build while it is visible. The overlay does NOT pause the game.

**Top progress bar (anchored top-left of viewport, full-width):**
- `ProgressBar` — full-width, 8px height, `step = 1`, `min_value = 0`, `max_value = 4`, `value = current_step`.
- Fill color: accent yellow `#F5C30D` (set via `add_theme_color_override("fill_color", ...)`).
- Background: dominant navy at 80% alpha.
- To the right of the ProgressBar, on the same horizontal strip: `Label` "Step {n}/4" — Label 14px semibold, brick white. Right-anchored, 16px right margin.

**Narration label (anchored bottom-third of viewport):**
- `PanelContainer` — centred horizontally, anchored 32% from the bottom of the viewport. Width: min(viewport_width * 0.8, 560px). Auto-height.
- Background: `StyleBox_panel` (dominant navy at 0.92 alpha, rounded 16px). Content margin: 16px.
- Inside: `HBoxContainer` (8px gap):
  - Arrow indicator `TextureRect` (`assets/icons/ftue_arrow.png`, 24×24px, new asset). Rotates to point toward the target entity using `get_viewport().get_camera_3d().unproject_position(target_world_pos)`. If the target is off-screen, the arrow is placed at the screen edge nearest to the target (off-screen indicator pattern). When no target (completion step): arrow hidden.
  - `Label` — `SIZE_EXPAND_FILL`, Body 16px regular, brick white, `autowrap_mode = TextServer.AUTOWRAP_WORD`.

**Arrow animation:** The `ftue_arrow.png` `TextureRect` has a `Vector2` position offset that oscillates: a `Tween` (looping) moves the TextureRect ±6px in the direction it is pointing, at 0.6s period (sinusoidal, `Tween.TRANS_SINE`, `Tween.EASE_IN_OUT`). This is the "bouncing arrow" effect. It uses only the existing tween system; no AnimationPlayer required.

**Step narrations (exact copy per DOCS §1.2, verbatim):**

| Step | i18n key | Copy |
|------|----------|------|
| Step 1 | `ui.ftue.step_1` | "Open the chest — you'll need what's inside before nightfall." |
| Step 2 | `ui.ftue.step_2` | "Try mining the tree. Tap and hold a tree block." |
| Step 3 | `ui.ftue.step_3` | "Try placing a wooden plank." |
| Step 4 (completion) | `ui.ftue.complete` | "That's it. The world is yours." |
| Step 4b (night approaching, parallel) | `ui.ftue.night_hint` | "Time to sleep. Walk to the bed." |

**Completion animation:** On step 4 trigger:
1. The narration label updates to the completion message, using Heading 20px semibold (not Body) — override via `add_theme_font_size_override`.
2. A `Tween` fades the label in (`modulate.a` 0 → 1, 0.5s, ease in-out).
3. After 3 seconds, the entire overlay `_root_container` fades out (`modulate.a` 1 → 0, 0.5s), then `queue_free()` is called.
4. `OnboardingTelemetry.log("ftue_complete")` is called.
5. `WorldSave.set_world_meta("ftue_complete", var_to_bytes(true))` is called.

**Night-approaching hint (parallel overlay):** If `WorldClock` transitions to `DUSK` while `current_step < 4`, a second label fades in below the primary narration label (8px gap, same panel, same font rung but brick-white 70% alpha) showing `tr("ui.ftue.night_hint")`. This hint does not advance the step counter. It disappears automatically when `WorldClock` transitions out of DUSK.

**Target entity highlighting:**
- Step 1 (chest): `ChestEntity.ftue_highlight = true` → activates a pulsing outline shader uniform on the ChestEntity mesh. Pulse frequency: 1.5 Hz, intensity oscillating 0.0 → 1.0.
- Step 2 (nearest tree trunk): The nearest wood_log VoxelTool position is identified by the FTUE overlay's `_find_nearest_tree()` method (scans a 20-block radius from the spawn point using VoxelTool.get_voxel). The position is passed to a `GPUParticles3D` node (`ftue_highlight_particles.tscn`, stub — emits a soft glow ring around the target block). Duration: 10 seconds regardless of completion, then particles stop.
- Step 3 (brick palette wood_plank slot): `BrickPalette._set_ftue_highlight("wood_plank", true)` — adds a 2px accent-yellow pulsing border to the `wood_plank` tile in the sidebar/bottom-sheet. Implemented via a `Tween` on the tile's `StyleBox` `border_color.a` (0.5 → 1.0 → 0.5 loop).

**FTUE does not run if:**
- `WorldSave.get_world_meta("ftue_complete")` is non-null (already completed).
- The player joined via deep-link (their `ftue_complete` is pre-set to true).
- The current mode is sandbox/creative (`Features.is_survival_mode()` returns false — the starter chest and bed are not guaranteed present in a sandbox world).

## Verdict

**APPROVED-WITH-RECOMMENDATIONS**

The design contract is complete and internally consistent. All 6 new surfaces and 3 modifications are fully specified with layout, typography, color, interaction, animation, and i18n keys. All upstream decisions from 06-CONTEXT.md, DOCS.md §1, 05-UI-SPEC.md, and the existing codebase are pre-populated. No design-system questions require user input.

**Recommendations before executor starts:**

1. **Avatar preset asset authoring is on the critical path.** The 8 preset tiles (`avatar_presets/preset_N.png`, 64×64px) must be commissioned before Surface 2 can ship. They need to represent diverse skin tones, gender presentations, and accessory choices. Until they exist, use solid-colour `ColorRect` nodes as placeholders with the preset index number as text. Flag this as a blocker for plan 06-02 (avatar creator plan).

2. **`Builder.apply_avatar_config(cfg: Dictionary)` method does not yet exist.** The 3D preview and the in-world avatar system both depend on this method. Plan 06-02 must add it to `src/builder/builder.gd`. The contract: it swaps `SpatialMaterial` colour values on named child nodes and sets `visible` on accessory child nodes. No mesh re-import. Pre-define the builder mesh node names (e.g. `Body`, `Legs`, `Head`, `Accessory`, `HandItem`) in the builder scene and document them in a comment.

3. **FTUE step 2 tree-scan performance.** `_find_nearest_tree()` using `VoxelTool.get_voxel()` in a 20-block radius loop runs ~8,000 iterations. This is acceptable as a one-shot call (not per-frame), but on Tier-3 it may still cause a 5–15ms hitch. The executor should call this method via `call_deferred` after the world scene has loaded rather than in `_ready`.

4. **Deep-link `--uri` argument on Godot 4.6 mobile must be validated with a test build before writing DeepLinkHandler.** 06-CONTEXT.md Area 5 notes the contingency (GDExtension plugin fallback). Plan 06-01 should include a spike task: build a minimal APK/IPA, register `cubicraftia://`, and verify `OS.get_command_line_args()` contains the URI on cold launch from the link. If it does not, the GDExtension fallback must be scoped into the plan before execution.

5. **`ui.ftue.step_3` copy ("Try placing a wooden plank.") differs slightly from DOCS §1.2 ("You can place anything in your inventory back into the world. Try placing a wooden plank.").** DOCS §1.2 narration step 6 uses the longer version; DOCS §1.2's summary list in the step-by-step uses the shorter version. The executor should use the longer copy: `tr("ui.ftue.step_3")` = "You can place anything in your inventory back into the world. Try placing a wooden plank." — this is the verbatim DOCS contract. This spec's copywriting table must be treated as corrected to match DOCS §1.2. (The i18n key is unchanged; only the msgstr value is corrected.)

6. **Title screen deep-link intercept racing condition.** If `DeepLinkHandler.invite_token_received` fires before `title_scene._ready()` connects to it (because `DeepLinkHandler` is an autoload that fires in `_ready` before the scene tree is fully built), the title scene will miss the signal. Fix: in `title_scene._ready()`, also check `DeepLinkHandler.get_pending_token()` (a new property that stores the last-received token until consumed). This prevents the race.
