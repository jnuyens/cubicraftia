    Read `src/builder/builder.gd` to understand the existing node structure, physics body type, and _ready() initialization sequence. Read `src/builder/builder.tscn` (if readable as text) to understand the current child nodes.

    Add these named child nodes to `builder.tscn`. Since .tscn files are text-based in Godot, add them as new sections. However, the cleanest approach in a headless environment is to add the nodes programmatically in builder.gd's _ready() if they don't exist (rather than editing the .tscn directly). Use this approach:

    In `builder.gd`, add a `func _setup_avatar_mesh_nodes() -> void:` called in `_ready()` that:
    - Creates a Node3D child named "AvatarMesh" if it doesn't exist
    - Inside AvatarMesh, creates 4 MeshInstance3D children: "Head" (BoxMesh 0.5×0.5×0.5), "Body" (BoxMesh 0.4×0.6×0.3), "Legs" (BoxMesh 0.4×0.5×0.3), "HandItem" (Marker3D parent with 5 MeshInstance3D children for each hand accessory option)
    - Positions them correctly (Head at y=1.4, Body at y=0.8, Legs at y=0.3 — approximate MiniFig proportions)
    - Creates StandardMaterial3D for each mesh with `albedo_color` set to default values
    - Stores references: `_head_mesh`, `_body_mesh`, `_legs_mesh`
    - Creates hand accessory nodes: `_hand_nodes: Dictionary[String, MeshInstance3D]` with keys "none"(invisible empty), "pickaxe", "lantern", "flower", "blank" — all hidden by default
    - Creates body accessory nodes: `_body_accessory_nodes: Dictionary[String, Node3D]` with "none", "backpack", "cape"

    For the hand/body accessory MeshInstance3D nodes: use simple BoxMesh stubs (0.1×0.3×0.1 for pickaxe, etc.) — the exact shape is not important for Phase 6; Phase 999.1 will replace these with real sculpted meshes.

    Add `func apply_avatar_config(cfg: Dictionary) -> void:`:
    - Guard: if not is_inside_tree(): return (prevents SubViewport timing issues)
    - Apply skin colour to head mesh: `_head_mesh.get_active_material(0).albedo_color = SKIN_COLOURS[cfg.get("skin_colour_index", 0)]`
    - Apply body colour: `_body_mesh.get_active_material(0).albedo_color = BODY_COLOURS[cfg.get("body_colour_index", 0)]`
    - Apply leg colour: `_legs_mesh.get_active_material(0).albedo_color = BODY_COLOURS[cfg.get("leg_colour_index", 0)]`
    - Set hand accessory visibility: hide all, show cfg.get("hand_accessory", "none")
    - Set body accessory visibility: hide all, show cfg.get("body_accessory", "none")
    - Note: head_shape and face_expression affect mesh scale/material texture — for Phase 6 v1, apply only a minor scale difference between shapes (square: scale 1.0, round: scale_x 0.9, tall: scale_y 1.2) via `_head_mesh.scale = ...`

    Add `func load_avatar_from_file() -> void:` called at end of _ready():
    - cfg = ConfigFile.new(); if cfg.load("user://avatar.cfg") == OK: build dict from [avatar] section keys; call apply_avatar_config(dict)
    - If file missing: call apply_avatar_config(DEFAULT_AVATAR_CFG) where DEFAULT_AVATAR_CFG is a constant with index 0 for all fields

    Define colour constants in builder.gd (must match avatar_creator.gd exactly — copy the arrays):
    - `const SKIN_COLOURS: Array[Color]` — 5 values
    - `const BODY_COLOURS: Array[Color]` — 10 values (same 10 used in avatar_creator.gd BODY_COLOURS)

    Also: in avatar_creator.gd (Plan 06-04 already created it), upgrade `_apply_config_to_preview()` to call `Builder.apply_avatar_config(cfg)` on the SubViewport builder instance instead of the direct material manipulation approximation. This is a one-line upgrade of the existing method.
