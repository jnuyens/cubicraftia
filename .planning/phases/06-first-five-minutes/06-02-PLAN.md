    - `extends Node`
    - `signal invite_token_received(token: String)`
    - `var _pending_token: String = ""`
    - `var _handled: bool = false`
    - `func _ready() -> void:` — iterate `OS.get_command_line_args()`. For each arg:
      - If `arg.begins_with("--invite=")`: extract token as `arg.substr(len("--invite="))`. If `token.length() >= 20` and not `_handled`: set `_pending_token = token`, set `_handled = true`, emit `invite_token_received.emit(token)`, return.
      - If `arg.begins_with("--uri=cubicraftia://invite/")`: extract token as `arg.substr(len("--uri=cubicraftia://invite/"))`. Same length check and guard.
    - `func get_pending_token() -> String:` — returns `_pending_token`.
    - `func consume_pending_token() -> String:` — returns `_pending_token`, then sets `_pending_token = ""` (one-time consume pattern for title_scene to call after connecting the signal).

    The 20-char minimum is the T-06-T1 client-side sanity check (from RESEARCH.md threat model). It does not replace server-side validation in FriendsClient.redeem_invite() — it only prevents trivially malformed tokens from triggering the join flow.

    - `extends Node`
    - `const MAX_EVENTS: int = 10_000`
    - `const FLUSH_INTERVAL_SEC: float = 60.0`
    - `var _queue: Array[Dictionary] = []`
    - `static func log(event_name: String) -> void:` — appends `{"ts": int(Time.get_unix_time_from_system()), "event": event_name}` to `_queue` on the singleton instance. Access singleton via `Engine.get_singleton("OnboardingTelemetry")` or rely on autoload singleton auto-name. Since GDScript static methods cannot access instance state directly, use `func log(event_name: String) -> void:` as an instance method and expose a convenience global via the autoload singleton name. Ensure it is callable as `OnboardingTelemetry.log("event_name")` from any script.
    - `func _ready() -> void:` — create a `Timer` node, `wait_time = FLUSH_INTERVAL_SEC`, `autostart = true`, connect `timeout` → `_flush_to_disk`, add as child.
    - `func _notification(what: int) -> void:` — if `what == NOTIFICATION_WM_CLOSE_REQUEST`: call `_flush_to_disk()`.
    - `func _flush_to_disk() -> void:` — loads `user://telemetry.cfg`, reads existing `event_count` from `[meta]` section, appends all queued events as `[event_N]` sections with `ts` and `event` keys, enforces 10,000-event cap by calling `_rotate_oldest(cfg, count - MAX_EVENTS)` if over limit, saves the file, clears `_queue`.
    - `func _rotate_oldest(cfg: ConfigFile, drop_count: int) -> void:` — reads all section names, sorts them, removes the oldest `drop_count` sections from the ConfigFile via `cfg.erase_section()`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS CLI args → DeepLinkHandler | Untrusted input: anyone can craft a CLI arg; token length check is client-side sanity only |
| DeepLinkHandler → FriendsClient.redeem_invite() | Server-side single-use validation enforced by Go signaling + Supabase RLS |
| OnboardingTelemetry → user://telemetry.cfg | App-sandbox file; iOS/Android OS sandboxing prevents other apps from reading it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-T1 | Tampering | DeepLinkHandler — spoofed deep-link with crafted token | mitigate | Client-side: token.length() >= 20 rejects trivially malformed tokens. Server-side: FriendsClient.redeem_invite() uses single-use token validation in Go signaling + Supabase RLS |
| T-06-D1 | Denial-of-Service | OnboardingTelemetry — log fills disk | mitigate | 10,000-event cap with _rotate_oldest() drops oldest events; user:// directory is OS-sandboxed with limited space on mobile |
| T-06-I1 | Information Disclosure | OnboardingTelemetry — event log contains PII | mitigate | Events store only unix timestamp (int) + event name (String from locked list); no user IDs, no emails, no positions |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No new package installations in this plan |
</threat_model>
