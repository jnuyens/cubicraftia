# Phase 2 Plan 08.5: Dual-Camera Builder (SpringArm3D Chase + FPV Toggle) Summary

**One-liner:** SpringArm3D chase camera with V-key toggle, scroll-wheel zoom [2–8 m], and refactored `get_crosshair_position/direction()` pointing to the active camera in both modes.

---

## What Was Built

### Task 1 — Dual-camera builder scene + script + input actions + crosshair API refactor

**builder.tscn** extended with:
- `CameraPivot` (Node3D, Y=1.6) — pitch applied here in CHASE mode
- `SpringArm3D` (length 4.0, margin 0.2, `collision_mask=1`) — retracts against WorldStaticBody / terrain
- `ChaseCamera` (Camera3D at SpringArm3D end) — active in CHASE mode
- Both Camera3D nodes `current=false` in scene; script activates correct one via `_apply_camera_mode()`

**builder.gd** additions:
- `enum CameraMode { FPV, CHASE }` + `camera_mode: CameraMode = CameraMode.CHASE`
- `@onready` refs: `camera_fpv`, `camera_pivot`, `spring_arm`, `camera_chase`
- Constants: `SPRING_ARM_MIN=2.0`, `SPRING_ARM_MAX=8.0`, `SPRING_ARM_STEP=0.5`
- `get_active_camera() -> Camera3D` — returns fpv or chase based on mode
- `toggle_camera_mode()` — flips mode, calls `_apply_camera_mode()`, persists to WorldSave
- `_apply_camera_mode()` — sets `.current` on fpv/chase, safe to call from tests without _ready
- Pitch pipeline: `camera_fpv.rotation.x` in FPV; `camera_pivot.rotation.x` in CHASE
- Scroll-wheel zoom guarded by `if camera_mode == CameraMode.CHASE` (no-op in FPV)
- `get_crosshair_position()` / `get_crosshair_direction()` refactored to use `get_active_camera()`
- `get_aim_origin()` / `get_aim_direction()` preserved as aliases (Plan 05 compatibility)
- T-CAM-01: defensive parse on WorldSave camera_mode read; unknown value → CHASE + `push_warning`
- T-CAM-02: `assert(spring_arm.collision_mask & 1 != 0)` in `_ready`
- First-frame default: if WorldSave open and no camera_mode key, writes `"chase"` explicitly

**project.godot** three new input actions:
- `toggle_camera_mode` — KEY_V (keycode 86)
- `camera_zoom_in` — MOUSE_BUTTON_WHEEL_UP (button_index 4)
- `camera_zoom_out` — MOUSE_BUTTON_WHEEL_DOWN (button_index 5)

**locale/en.po** three new keys:
- `ui.camera.mode_fpv` → "First-person view"
- `ui.camera.mode_chase` → "Third-person view"
- `ui.camera.toggle_hint` → "Press V to switch view"

### Task 2 — GUT tests: toggle + zoom + crosshair direction

**tests/unit/test_builder_camera.gd** — 4 tests, all GREEN:

| Test | What it checks |
|------|---------------|
| `test_toggle_swaps_active_camera` | FPV → CHASE → FPV toggle; `.current` flags and `get_active_camera()` return value |
| `test_zoom_clamped_to_min_max` | Spring length clamps to [2.0, 8.0] after 20 scroll steps past each extreme; constants verified |
| `test_zoom_noop_in_first_person` | FPV mode guard condition false; spring_length unchanged |
| `test_crosshair_direction_matches_active_camera` | FPV: rotated -90° Y → direction +X; CHASE: default rotation → direction -Z; `get_crosshair_position` == active camera position |

### Simplifications (within plan spec)

**1. [Plan-Sanctioned Simplification] Zoom tests use arithmetic over InputEvent synthesis**
- **Found during:** Task 2 implementation
- **Issue:** Headless GUT InputEvent synthesis for scroll events is unreliable (noted in plan spec: "since synthesising InputEvents in GUT is fiddly")
- **Fix:** Tests drive `spring_arm.spring_length` directly using the same `clampf + SPRING_ARM_STEP` arithmetic the handler uses, with the public constants. The FPV no-op test asserts the guard condition (`camera_mode != CHASE`) is false rather than simulating an event.
- **Plan approval:** The plan explicitly states "Acceptable simplification: just assert SPRING_ARM_MIN==2.0 and SPRING_ARM_MAX==8.0 and that clampf is used, via grep, as part of acceptance."
