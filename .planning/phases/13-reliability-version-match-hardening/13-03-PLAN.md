<objective>
Fix the concrete, reproducible RELY-04 bug (D-05): `FriendsClient.redeem_invite()` PATCHes
`invites?token=eq.<token>`; when the token is expired, already redeemed (single-use), or does
not exist, PostgREST returns HTTP 200 with an EMPTY array. `_on_invite_completed()` currently
treats ANY 200/201/204 as unconditional success and emits `friendship_created("")` regardless.
`title_scene._on_friendship_created("", token)` then calls `start_peer("", 0)` (empty
session_id) and unconditionally changes scene to `main_scene.tscn`. This is the exact
"silent no-op or hang" failure mode RELY-04 targets, reproduced directly from the shipped code,
not a hypothetical.

Purpose: a stale/invalid invite link must resolve to `NetworkManager.report_connection_problem`
with reason "expired" and restore the title screen, not a broken silent join.
Output: `FriendsClient.invite_redeem_failed(reason)` signal; guarded `title_scene.gd` handlers.
</objective>
