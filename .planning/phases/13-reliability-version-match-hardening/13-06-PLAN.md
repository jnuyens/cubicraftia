STATE_RECONNECTING` (sets `ui.join.status_loading`), and `STATE_DISCONNECTED` (calls
`_show_error`) — the `STATE_DISCONNECTED` arm is removed entirely (superseded by the
connection_problem-driven teardown below); the `STATE_FAILOVER_WAITING, STATE_RECONNECTING` arm
is updated per RELY-02/03 Case 2.

`src/ui/join_screen.tscn` current node tree under `Overlay`: `Content` (Heading, StatusLabel) and
`ErrorContent` (ErrorHeading, ErrorBody, BackButton) — `ErrorContent` and its 3 children are
REMOVED entirely; `Content` gains a new `Spinner` node between `Heading` and `StatusLabel`.

`src/ui/handover_screen.tscn`'s `Spinner` node (AnimatedSprite2D, `sprite_frames` a
`SpriteFrames` sub_resource with a single-frame `default` animation at `speed = 2.0`, `loop =
true`, referencing `icon_spinner.png`) is the EXACT pattern to copy verbatim for
`join_screen.tscn`'s new `Spinner` node — same asset, same speed, per the UI-SPEC's explicit "do
not create a second spinner asset or a different frame rate" instruction.

`src/ui/network_hud.gd` current: `show_relay_badge(peer_id: int, show: bool)` toggles
`RelayBadge.visible` (default `false` in `_build_peer_row`); `RelayBadge` Label already has

changes the DEFAULT visibility to always-`true` and replaces the toggle API with a two-state

built programmatically in `_build_peer_row`, not in `network_hud.tscn`).

`NetworkManager.connection_type_changed(peer_id: int, is_relay: bool)` (Plan 13-04) is the sole
new signal source for the badge.
