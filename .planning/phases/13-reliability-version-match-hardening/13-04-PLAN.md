<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Joining peer → host (P2P RPC) | The peer's self-reported PROTOCOL_VERSION is untrusted input to the host; the host is the sole authority on acceptance (D-08 host-authoritative) |
| ICE candidate SDP strings | Locally-observed transport metadata, not attacker-controlled in a way that changes trust, but misclassification only affects a cosmetic badge, never gameplay |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-04-01 | Spoofing | `_report_protocol_version` RPC | mitigate | `@rpc("any_peer")` but the HOST is the sole decision-maker (`if not multiplayer.is_server(): return`); a peer cannot force another peer to be accepted/rejected, only report its own version |
| T-13-04-02 | Tampering | Version-mismatched peer bypassing rejection | mitigate | `peer_connected` is withheld (`_pending_version_peers` gate) until the version RPC round-trip completes; no Inventory event or snapshot RPC is ever addressed to a peer for which `peer_connected` was never emitted, since all broadcast paths (`broadcast_event`, `_broadcast_snapshot_to_peers`) target the full multiplayer peer set, not the UI-visible peer list — noted as an accepted residual: the WebRTC transport-level connection exists for a few hundred ms before rejection completes, but no gameplay-state RPC is host-initiated toward a specific peer_id before this handshake resolves |
| T-13-04-03 | Elevation of Privilege | `_receive_connection_rejected` RPC | mitigate | `@rpc("authority")` — only the host (peer_id 1) can tell a peer it was rejected, mirroring the existing `_receive_kicked_notice` pattern |
</threat_model>
